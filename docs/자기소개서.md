# 자기소개서

> **김선준**    1993년생 · 경력 4년차 · Agentic AI 엔지니어
> "데이터가 흐르는 파이프라인을 만들고, 그 위에서 Agent를 구현하는 엔지니어"
>
> UNIST에서 추천 시스템을 연구했습니다. 사용자 선호를 벡터로 바꾸고 유사도로 찾는 작업을 하다 보니, 자연스럽게 벡터 DB와 임베딩 검색 쪽으로 넘어왔습니다. 졸업 후에는 Skylife 영화 추천, 부산관광공사 여행 챗봇(현재 상용 운영 중)처럼 벡터 검색 기반 서비스를 만들었고, 이후 vLLM 서빙, Agentic RAG, Reflexion Agent까지 작업 범위를 넓혀 왔습니다. 모델 하나 띄우는 게 아니라, 데이터 수집부터 전처리, 벡터화, 검색, 생성, 서빙까지 직접 손대는 편입니다.
>
> [개발 전략]
> 1. **파이프라인 전 구간에 대한 고려**: 전처리에서 병목이 터지거나, 후처리에서 데이터 포멧이 잘못 만들어지거나, 어떤 한 구간에서 문제가 발생하면 모델이 아무리 좋아도 전체 파이프라인이 무너집니다. 데이터 수집, 임베딩, 검색, 서빙 — 어느 한 구간이 빠져도 서비스가 안 되기 때문에, 설계시 모든 단계를 고려합니다.
> 2. **데이터 품질이 모델 성능을 결정**: 같은 RAG 구조라도 청크를 어떻게 자르고, 어떤 메타 정보를 붙이느냐에 따라 검색 정확도가 달라집니다. 100자 이하 청크 필터링, KoNLPy 토큰 검증 같은 작업을 전처리 단계를 중요시합니다.
> 3. **복잡한 태스크는 단순한 태스크로 분해부터**: 큰 문제를 한 번에 풀려고 하면 어디서 막혔는지도 파악이 안 됩니다. RAG 시스템을 만들 때도 전처리, 임베딩, 검색, 리랭킹, 생성, 안전 검증을 각각 독립된 단위로 쪼개서 하나씩 검증했고, vLLM API도 요약·분류·태깅을 별도 에이전트로 분리한 뒤 LangGraph로 흐름을 엮었습니다. 단위가 작아야 디버깅이 빠르고, 설계도 유연해집니다.
> 4. **적절한 레퍼런스 참고로 불필요한 시행착오 줄이기**: 새 문제를 만나면 코드부터 치는 것은 비효율적이라고 생각합니다. 논문, 공식 문서, 검증된 구현체를 먼저 자료 조사를 합니다. 석사 때 연구한 임베딩-검색 구조가 pgvector와 Milvus 프로젝트에 그대로 이어진 것처럼, 이미 검증된 접근법을 우리 상황에 맞게 적용시키는 것이 더 효율적이라고 생각합니다. RAG에서 Dense+BM25 하이브리드 검색을 택한 것도, Reflexion Agent에서 ReAct 논문의 루프 구조를 가져온 것도 레퍼런스를 먼저 참고하여 구현한 결과물입니다. 남이 이미 부딪힌 벽을 똑같이 부딪힐 이유가 없고, 그 시간을 아껴야 레퍼런스가 없는 문제에 집중할 수 있습니다.
> 5. **연구 자료와 히스토리 정리(Documentation)**: 조사한 내용, 시도한 접근법, 실패 원인을 그때그때 기록으로 남깁니다. 기록이 없으면 이전에 개발할때 왜 이 구조를 택했는지, 어떤 대안을 검토했는지 기억에 의존해야 하고, 같이 협업하는 동료에게도 맥락 전달이 제대로 이루어지지 않습니다. Notion 또는 confluencer같은 documentation 도구를 활용해 기술 조사, 설계 판단 근거, 트러블슈팅 과정을 기록하고 이 기록이 이후 프로젝트에서 의사결정 속도를 높여주는 자산이 됩니다. 추가로 Wikidocs 같은 툴을 활용해 연구자료들을 읽기 쉽게 풀어내어 저서로 만들기도 합니다.

## 학력

UNIST(울산과학기술원) 산업공학과 석사 (2023 졸업)

석사 논문으로 Convolutional Autoencoder 기반 추천 시스템을 연구했습니다. 사용자 선호를 잠재 벡터(latent vector)로 표현하고, 그 벡터 간 유사도로 아이템을 추천하는 구조입니다. 이때 익힌 임베딩-검색 파이프라인이 졸업 후 pgvector, Milvus 구현의 기반이 되었습니다.

논문: *Personal recommender system via convolutional autoencoder with conditioning augmentation*
