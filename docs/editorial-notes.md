# 작성 기준과 근거

이번 정리는 Claude에서 작성한 [「미국 테크 이력서 작성 가이드와 자료 모음」](https://claude.ai/artifact/US2YiKg6LcuzFmoaxK1oBc)을 기준으로 했다. 2026-11-21 작성 기록의 본문을 확인했으며, 한 단 구성, 최근 경험 우선, 행동·결과 중심 문장, 수치의 사실 보존 원칙을 적용했다. 개인 연락처는 기존에 공개된 이메일만 사용했다.

## 문서별 적용

영문 이력서는 Experience·Projects·Skills·Education의 표준 제목과 텍스트 중심 형식으로 구성했다. 핵심 성과만 남기고 기술 상세와 현재 프로젝트의 전체 구성은 경력기술서와 프로젝트 문서에 배치했다. 특정 채용공고가 지정되지 않아 AI/ML·AI Agent 엔지니어의 기본 이력서로 작성했다.

성과는 행동·관측한 결과·방법이 연결되도록 썼다. 정량 성과가 확인되지 않은 현재 프로젝트에는 구현 범위와 검증 단계를 적었으며, 생산성 개선율·매출·사용자 수를 만들지 않았다. Company Brain과 DCA의 합성 시험은 실제 고객 업무 성과와 구분했다.

원칙의 공개 출처는 [Tech Interview Handbook](https://www.techinterviewhandbook.org/resume/), [Tech Resume Checklist](https://github.com/n2cholas/resume-checklist), [EngineeringResumes 작성 가이드](https://github.com/r-engineeringresumes/subreddit-wiki/blob/main/wiki/index.md)다. 가이드에 소개된 외부 skill이나 이력서 업로드 서비스는 설치·실행하지 않았다.

내부 자료에서는 공개 설명에 필요한 역할·기술·구현 상태만 추렸다. 고객 원문, 계약·금액, 내부 저장소 주소, 실행 식별자와 자격 정보는 포함하지 않았다. 이 문서 작업을 위해 원 프로젝트의 실행·시험·배포를 재시작하지 않았다.

## 제출 전에 확인할 사실

- 회사별 공식 입·퇴사 연월과 직함. 프로젝트 기간을 재직기간으로 대신하지 않았다.
- 대상 공고, 근무 희망 지역, LinkedIn 등 추가 연락처. 확인되지 않은 개인정보·취업 자격은 기재하지 않았다.
- 과거 수치의 평가 집합·측정 환경·기간. 현재 문서는 기존 공개 수치를 재평가한 결과가 아니다.
- 현재 프로젝트의 팀 규모와 개인별 세부 기여율. 전체 작업을 단독 수행했다고 표현하지 않았다.

README의 기존 기술 상세는 [기존 프로젝트 문서](projects/prior-projects.md)로 재구성했고, 이전 원문과 도표는 Git 이력에서 확인할 수 있다. 기존 이미지 파일은 보존했다.
